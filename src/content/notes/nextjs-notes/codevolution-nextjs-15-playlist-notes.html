055:50

Routing

Core idea

  • Next.js uses file-system routing: app/about/page.tsx maps to /about.
  • Each folder is a URL segment; the exported React component is rendered for that route.
  • Routes are server components by default, so no use client directive is needed for static UI.
Concrete example

'app/products/page.tsx' becomes '/products' without a route table.

Benefits

Routes stay colocated with their UI and data needs.

Trade-offs & cautions

Renaming folders changes public URLs and must be treated as an API change.

Working rule

Routes are server components by default, so no use client directive is needed for static UI.

  • Route handlers live inside app but cannot share the same segment as page.tsx.
  • They are appropriate for public endpoints, webhooks, and backend-for-frontend logic.
Concrete example

Create 'app/api/comments/route.ts' with 'GET' and 'POST' exports.

Benefits

Provides standards-based HTTP endpoints inside the same application.

Trade-offs & cautions

Handlers can duplicate server-component data access and become an unnecessary internal API layer.
